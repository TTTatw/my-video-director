# Product Intake — 产品画像

把一张产品图片变成**可做创意的上下文**。这一步不产出创意，只产出"这个产品是什么、说给谁、像什么样"。

## 输入
- 产品图片（1 张或多角度）
- 可选：目标人群 / 想卖点 / 场景一句话

## 产出（一个结构化 block）

```markdown
## 产品画像
- 品类：____
- 核心卖点：____（图片上能看出的 + 合理的，[待确认]标出）
- 目标人群：____（年龄用描述，不用数字）
- 调性/色板：____（从图片配色/材质/风格概括）
- 人群痛点：____（这个品类通常替用户解决什么）
- 使用场景：____（何时、何地、和谁）
- 语言风格：____（口语/高级感/亲切/有梗）
```

## 规则

1. **先列"客观可读"**：图片里能确认的形状、材质、配色、风格、明显卖点。这是底座。
2. **再给"创意解读"**：这个产品放在真实人群里意味着什么。**和客观信息分开标注**，别混。
3. **不虚构 claim**：图片看不出的功能、效果写 `[待确认]`。宁可少，不可编。
4. **人群用描述不用数字**：不写"25~35 岁"，写"通勤路上的年轻人、运动后要补水的人"。
5. **抓"调性"很关键**：这个产品是高级感、元气感、机能感、还是治愈感？它决定 video 的镜头和口吻。

## 判断优先级

如果图片信息不足（比如黑白产品图、没场景），**优先靠模型对该品类的常识**搭一个"默认画像"，但同时把几个不确定点列为 `[待确认]`，让用户补一句。不要让画像空转。
